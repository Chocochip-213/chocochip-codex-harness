# screen: 읽히는 화면

이 글이 스킬 전문이다. 전문이 현재 문맥에 있으면 이 SKILL.md를 다시 열지 않고, 없거나 불확실하면(자동 압축 뒤 등) 다시 읽는다. 화면 구현 지침이며 단계 보고·기록은 AGENTS.md를 따른다. 계획에 있는 화면 요소만 다룬다. 아래의 띠·표·범례 같은 요소는 계획에 있을 때만 만들고, 빈 상태·오류 문구처럼 이미 있는 요소의 상태는 쓴다. 과제에 기존 화면 코드가 있으면 그 구조와 모양을 먼저 따른다. 새 기능·화면 요소·패키지가 필요하면 AGENTS.md대로 묻는다.

## 0. 디자인 계획 (화면을 처음 만들 때 한 번, 코드 전에)
- 첫 화면 구현 안에서 한 단락으로 정해 스타일 맨 위 주석에 둔다(별도 승인·비교 단계는 만들지 않는다): 색 토큰 4~6개(바탕·면·글자·옅은 선·강조 하나·상태색), 글자 역할(본문·숫자·제목), 화면마다 배치 한 줄.
- 과제의 업무 세계에서 색이나 모양 하나를 가져와 가장 중요한 결과 영역 한 곳에만 강하게 쓰고, 나머지는 조용하게 둔다.
- 조작(입력·버튼)과 결과가 한 화면에 있으면 데스크톱에서 두 열(왼쪽 좁게 조작, 오른쪽 넓게 결과)로 나눈다.

## 1. 바탕
- 스타일은 한 곳(CSS 파일 하나나 `<style>` 하나)에 두고, 맨 위 `:root`에 색·간격·글자 크기를 변수로 둔다. 외부 CDN·웹 폰트·CSS 프레임워크는 쓰지 않는다(과제 코드가 이미 쓰면 따른다). 글꼴은 `system-ui, "Segoe UI", "Malgun Gothic", sans-serif`.
- 상태색(정상·주의·오류)은 글자와 함께 쓴다(색만으로 뜻을 전하지 않는다). 글자와 바탕 대비는 4.5:1 이상.
- 글자 크기는 본문·소제목·제목 세 단계, 줄 간격 1.5 안팎, 간격은 4·8·16·24px만. 테두리·상자는 정보 묶음을 가를 때만.
- 로그인한 사람·역할, 지금 적용된 입력·마지막 계산 시각처럼 계획에 있는 상태는 위쪽 띠에 짧은 배지로 모은다.
- README가 모바일을 빼면 데스크톱 폭(1280px 안팎)만 맞춘다. 가로 스크롤은 넓은 표 안에서만 생기게 한다. 키보드로 갈 수 있게 하고 `:focus-visible` 테두리를 지우지 않는다.

## 2. 표
- 머리줄은 스크롤해도 보이게(`position: sticky`). 숫자는 오른쪽 정렬과 `font-variant-numeric: tabular-nums`, 단위는 머리줄에. 날짜·시각 형식은 한 가지로.
- 긴 값은 말줄임(`text-overflow: ellipsis`)하고 `title`에 전체 값을 둔다.
- 목록이 크면 서버에서 계획에 있는 필터·쪽 나누기로 나눠 보낸다(전체를 한 번에 내려 보내지 않는다).
- 비어 있으면 카드 한 장에 '무엇이 없어서 비었는지와 무엇을 하면 채워지는지'를 쓴다.

## 3. 폼과 버튼
- 이름표는 입력칸 위에, 단위·허용 범위는 칸 옆에. 입력 오류는 그 칸 가까이에 원인과 고치는 법을 쓰고, 위치 정보(파일·행·열 등)가 있으면 함께 보인다.
- 버튼 글자는 동작 이름("다시 계산", "이 데이터 적용")으로 쓰고, 주 동작 하나만 강조색, 나머지는 테두리 버튼으로 한다. 동작이 끝나면 결과를 같은 자리에 남긴다(건수가 의미 있으면 건수도).

## 4. 상태
- 데이터를 보이는 곳마다 비어 있음·오류(무엇이 왜 안 됐고 다음에 무엇을 할지)·정상을 기존 요소 안에서 나눠 보인다(이를 위해 새 기능을 만들지 않는다). 지난 결과를 보일 때는 언제·어느 입력의 결과인지 붙인다.

## 5. 그래프·도표 (좌표나 관계를 그릴 때)
- 서버가 SVG 문자열로 만들어 내려 준다(과제 코드가 이미 다른 방식이면 따른다). 좌표 변환과 라벨 배치 계산은 함수로 나눠 테스트한다.
- `viewBox`를 고정하고 좌표 범위에 여백 6% 안팎을 둔다. 가로세로 비율을 지킨다(`preserveAspectRatio="xMidYMid meet"`). 판은 옅은 면이나 격자로 채워 노드가 적어도 비어 보이지 않게 한다.
- 그리는 순서: 옅은 전체 → 고른 것 → 라벨. 모든 것을 한꺼번에 진하게 그리지 않는다. 계획에 있는 선택 요소로 하나(또는 몇 개)를 고르게 하고 나머지는 옅게(투명도 0.2 안팎) 하거나 숨긴다.
- 방향이 있는 선은 화살표(`marker`)를 단다. 같은 두 노드 사이를 오가는 선은 살짝 휘게 그린다. 노드 종류는 모양으로 나눈다.
- 라벨은 노드마다 후보 자리 몇 곳(위·아래·좌·우·대각) 가운데 다른 라벨·노드·선·판 밖과 겹치지 않는 곳에 둔다. 다 겹치면 짧은 번호만 남기고 전체 이름은 `<title>`이나 옆 표에 둔다. 글자에 바탕색 외곽선(`paint-order: stroke`)을 준다.
- 범례가 있으면 판 안 한쪽에 둔다. 숫자는 그래프만으로 읽게 하지 않고 계획에 있는 표를 옆이나 아래에 둔다. 계산으로 정해지는 표시는 계산 함수가 낸 값만 그린다.

## 6. 확인 (스크린샷·헤드리스 브라우저는 쓰지 않는다)
- curl로 응답·필수 내용·상태 문구를 확인한다.
- 사용자에게 볼 곳을 세 줄 이내로 준다: 어느 역할로 무엇을 누르면 무엇이 보여야 하는지, 겹치거나 잘리는 곳이 없는지. 배치·겹침·잘림은 사용자가 보기 전까지 미확인으로 적는다.
