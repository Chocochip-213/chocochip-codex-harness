# relay: 담당자 답 정리 (질문 세션, 개발 중에도 씀)

코드는 고치지 않고 행 대조도 하지 않는다.

## 1. 기록
- 협업 기록에 한 줄씩 추가한다: 시각 / 보낸 질문(원문 그대로. 사용자가 고쳐 보냈다고 하지 않았으면 직전 초안) / 담당자 답(그대로. 사용자가 요약해 붙였으면 '요약'이라고 적는다) / 결정. 파일은 README가 정한 협업 기록, 없으면 COLLAB.md. 질문 초안과 사용자에게 보인 선택표는 파일에 쓰지 않는다.
- 요구 확인표의 상태를 고친다. README 문장과 담당자가 말한 것만 '확정'이다. 담당자가 답하지 않은 처리안은 '가정'으로 둔다. 내가 답을 해석해 채운 부분은 '가정'으로 적는다.
- 개발 시작 메모가 이미 있으면, 바뀐 것을 메모 끝에 '합의 뒤 변경'으로 덧붙이고 결정 기록에도 한 줄 쓴다.

## 2. 짚을 것
- README와 다른 답: "README에는 A, 담당자는 B"로 적고, 어느 쪽인지 묻는 질문을 만든다.
- "구체적으로 물어봐 달라"는 답: 앞 질문을 실제 데이터 한 건을 짚는 질문으로 바꾼다.
- "알아서 하세요": 결과(건수나 핵심 결과)를 크게 바꾸는 것만 세 개 이내로 골라 처리안 두셋과 영향 건수, 추천을 사용자에게 보이고, 사용자가 고른 것을 '가정(사용자 결정)'으로 적는다. 나머지는 추천안을 '가정(기본값)'으로 적고 한 줄 목록으로 보인다(사용자가 바꾸라고 하면 바꾼다). 한 번만 묻는다. 다음 메시지에 "이렇게 정했습니다" 한 줄로 알린다. 범위 합의로 보지 않는다.
- 묻지 않은 새 사실·주제(기간 중 바뀐 것, 알려진 문제, 새 조건, '이런 것도 확인해 보라')가 답에 있으면: 확인표에 새 행으로 넣고, 결과를 바꿀 수 있으면 '질문'으로 둔다.
- 앞선 답과 모순되면 바로 짚는다.
- 담당자가 되묻거나 질문을 이해하지 못했으면: 같은 질문을 실제 데이터 한 건과 쉬운 말로 다시 쓴 답장을 만든다.
- 일부만 답했거나 "너무 많다·길다"고 하면: 답 안 된 질문 중 결과를 가장 크게 바꾸는 것 하나만 두세 줄로 다시 묻는다. 그 뒤로는 담당자가 받아 준 개수만큼만 한 메시지에 넣고, 답 안 된 나머지는 '다음에 물을 것'으로 남긴다. 협업 기록에 '한 번에 n개'를 적어 다음 초안도 따른다.

## 3. 다음 메시지 초안 (둘 중 하나, 코드 블록 하나로)
- '질문'이 남았으면: 결과를 크게 바꾸는 것부터 세 개 안팎을 넣는다. 질문 하나에 결정 하나, 처리안과 다른 선택지 하나, 영향 건수를 붙인다. 모양은 "이 경우는 이렇게 처리하려고 합니다. ① [실제 데이터 한 건] → [처리안] … 다르면 말씀해 주세요." 넣지 못한 것은 '다음에 물을 것'으로 남긴다.
- 결과를 바꾸는 항목이 모두 확정·가정이면: 범위 합의 메시지. 만들 것 한 줄, 핵심 기준 한 줄, 이번에 만들지 않을 것과 이유 한 줄, 성공 기준 한 줄, 그리고 '정해 둔 기본값' 목록: 확인표의 '가정' 가운데 업무 기준(AGENTS.md에서 담당자에게 묻는 것)은 하나도 빼지 않고 번호를 붙여 한 줄씩 쓴다("<항목>: <기본값>. 다르면 <무엇이 바뀌나>"). 구현 방식의 가정은 넣지 않는다. 끝에 "이대로 진행해도 될까요? 기본값 중 다른 것은 번호로 말씀해 주세요. 제가 여쭤보지 않았지만 알아 두면 좋은 게 있을까요?". 이 턴에서는 개발 시작 메모를 쓰지 않는다.
  - 초안 위에 사용자에게 먼저 묻는다: 성공 기준과 '만들지 않을 것'이 이대로 맞는지, 두 조건이 부딪치면 무엇을 지키고 무엇을 조정할지. 사용자가 고치면 초안을 고쳐 다시 준다.
- 업무 말로 쓴다.

## 4. 합의가 끝나면: 개발 시작 메모
담당자가 범위 합의 메시지에 동의한 답을 붙여 넣었을 때만 쓴다. 답에 새 사실이나 바꿀 기본값이 섞여 있으면 쓰지 않고 1번부터 다시 한다. 계획 문서 맨 위에 '개발 시작 메모' 절을 쓰고 커밋한다. 개발은 새 세션이 이 메모만 보고 시작하므로, 대화에만 있는 내용이 없게 쓰되 한 화면 안팎으로 줄인다.
- 만들 것과 제출물
- 판정 기준과 출처(확정·가정 구분)
- 이번에 만들지 않을 것과 이유
- 데이터 처리 방침(이상한 점마다 어떻게 처리하는지)
- 환경(파이썬, pip, 포트)
- 시간 기준점
- 남은 가정과 '다음에 물을 것'

쓴 뒤 사용자에게 다음 두 가지를 알려 준다: `/new`로 새 세션을 연다 → `/plan`에서 "AGENTS.md와 계획 문서의 개발 시작 메모를 읽고 그대로 계획 세워 줘".

## 5. 끝에
- `EXPLAIN.md`의 '담당자와 정한 것' 절에 한두 줄을 덧붙인다: 무엇을 왜 물었고, 답으로 무엇이 바뀌었나.
- 사용자에게 한 줄: 합의 전이면 남은 질문 수와 가정, 합의 뒤면 이번 답이 바꾼 것.
