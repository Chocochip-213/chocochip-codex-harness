# chocochip-codex-harness

Codex로 데이터 과제를 할 때 쓰는 개인 작업 규칙, 스킬 다섯 개, 점검 도구입니다.
과제의 판정 로직이나 화면, 결과물은 들어 있지 않습니다. 점검·기록·검증 절차만 담았습니다.

## 설치 (한 줄)

과제 작업 폴더 맨 위에서, codex를 켜기 전에 shell 탭에 칩니다. 승인 창 없이 끝납니다.

```bash
git clone --depth 1 https://github.com/Chocochip-213/chocochip-codex-harness /tmp/h && bash /tmp/h/setup.sh
```

- 잘 깔렸는지: `bash .harness/tools/selftest.sh` → '실패 0'.
- Codex에게 시켜도 됩니다. 과제 폴더에서 codex를 켜고 이렇게 말합니다.
  `깃허브 Chocochip-213/chocochip-codex-harness 를 /tmp/h 에 clone해서 이 폴더에 설치해 줘.`
  샌드박스가 네트워크와 `.agents`·`.codex`·`.git` 쓰기를 막아서 승인 창이 두 번(clone, 설치) 뜹니다. 둘 다 y. 설치와 커밋까지 끝나면 `/new`를 쳐야 스킬과 금지 규칙이 적용됩니다.
- `/tmp/h`가 이미 있으면 `bash /tmp/h/setup.sh`만 다시 실행합니다. 설치하다 멈췄을 때도 같은 명령을 다시 실행하면 이어서 깝니다.
- 'git 사용자 이름·이메일이 없습니다'가 나오면 안내대로 `git config` 두 줄을 친 뒤 다시 실행합니다.
- 과제에 같은 폴더 이름의 스킬(`.agents/skills/verify` 등)이나 하네스가 만들지 않은 `.harness` 폴더가 있으면, 또는 홈 폴더에서 실행하면 아무것도 바꾸지 않고 멈춥니다. 다른 폴더에 같은 스킬 이름이 있으면 경고만 하니, 그때는 "`.agents/skills/<이름>/SKILL.md`를 읽고 그대로 해 줘"로 부릅니다.
- 설치가 하는 일: AGENTS.md(과제 것이 있으면 끝에 덧붙임), `.agents/skills` 다섯 개, `.harness/` 점검 도구, `.codex/rules/chocochip-codex-harness.rules`(git push·원격 저장소 추가·gh·`--no-verify` 커밋 금지. 기본 승인 설정을 넓히는 허용 규칙은 없음), `.codex/config.toml`(추론 강도: 평소 medium, `/plan` high. 과제에 이미 있으면 넣지 않음), `.git/info/exclude`에 `.env`·`.ai_env` 같은 키 파일 제외, `.git/hooks/commit-msg`(Codex가 한 커밋의 메시지가 '타입(범위): 한국어 요약'이 아니면 막음. 사람·플랫폼 커밋은 검사하지 않음. 과제 훅이 있으면 넣지 않음). 그리고 하네스 파일만 따로 커밋합니다.

## 흐름

| 세션 | 언제 | 칠 것 |
|---|---|---|
| 질문 세션 | 과제를 받으면 | `$kickoff 남은 시간 2시간 50분` → 담당자 답마다 `$relay` → 범위 합의 메시지에 담당자가 동의하면 `$relay`가 계획 문서에 '개발 시작 메모'를 씀 |
| 개발 세션 | 합의 뒤 | `/new` → `/plan` "AGENTS.md와 계획 문서의 개발 시작 메모를 읽고 그대로 계획 세워 줘. 제출물·성공 기준·받는 장면의 항목마다 어느 단계가 만드는지 번호를 붙여 줘('못 물음'·'없음'은 빼고, 한 단계가 여러 항목을 맡아도 된다)" → Esc, Shift+Tab → "1단계 해 줘." → 한 단계씩 → `$verify` → `/new` → `$wrapup` → `$weakness` |

질문과 개발을 다른 세션으로 나누는 이유: 담당자 대화와 데이터 점검 출력이 개발 중 컨텍스트를 채우지 않게 하고, 개발 세션은 메모라는 정리된 기록에서 시작하게 하려는 것입니다.
`$verify`와 `$wrapup`은 지금까지의 대화를 넘기지 않은 새 에이전트(`spawn_agent`, `fork_turns: "none"`)에게 검증·검토를 맡깁니다. 만든 쪽이 자기 결과를 스스로 확인하지 않게 하려는 것입니다. 새 에이전트에게는 README, 요구 사본(개발 시작 메모와 담당자 확인 기록을 옮긴 `verify/spec_N.md`), 데이터만 읽게 하고 계획 문서·구현 코드·결정 기록·구현 값·출력 파일은 열지 않게 합니다. 새 에이전트를 쓸 수 없는 환경이면 스킬이 직접 합니다.

## 들어 있는 것 (설치 뒤 위치)

| 위치 | 하는 일 |
|---|---|
| `AGENTS.md` | 공통 규칙: 한국어, 결과·구조를 바꾸는 선택은 사용자에게 선택지·영향·추천을 붙여 묻기, 단계 보고 끝에 직접 읽을 함수·확인 질문·다음에 정할 것, 작업 내용을 밖으로 보내지 않음, 한 단계씩, 짧은 결정 기록(계획 문서에는 계획만, 질문·답은 협업 기록), 묻지 않은 기본값은 담당자에게 알림, 완료 전 다시 실행한 증거, 판정 단계의 행 대조, 판정과 화면 분리(결론·등급도 계산으로), 중간 산출물은 커밋 안 함, 반복 오류 때 원인부터, 요청 안 한 기능은 묻기, 하위 에이전트는 기록·커밋 안 함 |
| `.codex/rules/chocochip-codex-harness.rules` | git push·원격 저장소 추가·gh·`--no-verify` 커밋은 승인 창에서 허용해도 실행 안 됨(새 세션부터). 허용 규칙은 두지 않아 커밋은 승인 창에서 y |
| `.codex/config.toml` | 추론 강도: 평소 medium, 계획 모드(`/plan`) high. `/model`로 고르면 그 세션은 고른 값이 우선 |
| `EXPLAIN.md` (작업 중 생김, 커밋 안 함) | 설명 노트: kickoff의 '과제 한눈에', relay의 '담당자와 정한 것', 단계마다 정한 것과 근거·버린 대안·내가 바꾼 것 |
| `.agents/skills/kickoff` | 사용자용 '과제 한눈에' 요약, 환경·README·데이터 점검, 요구 확인표(확정·가정·질문·정의 확인, 데이터만 봐서는 알 수 없는 기록 방식·기간 중 변경·받는 쪽 양식·조치 비용 포함), 담당자 첫 질문 초안(데이터 질문: 실제 데이터 한 건과 처리안·다른 선택지, 장면 질문 하나: 결과로 누가 무엇을 정하고 선택지마다 드는 비용이나 지킬 것) |
| `.agents/skills/relay` | 담당자 답 기록, README와 다른 점, 답에 나온 새 이름 한 번 추적, 다음 확인 메시지, 범위 합의(정해 둔 기본값 목록 포함), 개발 시작 메모 |
| `.agents/skills/verify` | 웹이면 서버가 지금 코드로 도는지부터(라우트별 curl을 한 스크립트로, 상태를 바꾸는 요청은 되돌림), 새 에이전트의 독립 재계산(핵심 결과에 닿는 가정은 다른 안으로도 계산), 레코드별 차이 파일, 행 대조 |
| `.agents/skills/wrapup` | 요건 대조, 새 에이전트의 검토(요청 안 한 동작, 빠진 구현, 사용자에게 보이는 화면), 10분 안에 읽을 제출 문서, 계획 문서를 지금 상태로 정리, 키·개인정보 점검. 스킬 안에서는 고치지 않고 고칠 후보를 맨 끝에 한 번에 묻는다 |
| `.agents/skills/weakness` | 남은 약점, 설명 노트를 지금 코드에 맞추기, 한 화면 요약(구조·핵심 숫자·약점·입력 하나의 경로), 사용자가 자기 말로 정리, 점검 질문 |
| `.harness/tools/env_check.py` | 파이썬·pip·PyPI 접속·이미 있는 패키지·포트·git·샌드박스 여부 |
| `.harness/tools/profile_data.py` | CSV·TSV·JSON·JSONL·SQLite의 결측, 자리표시 값, 숫자 이상(음수·0·IQR 밖), 날짜 모양 섞임·없는 날짜, 표기 변형, 중복, 개인정보 모양 |
| `.harness/tools/join_check.py` | 조인 전에 키 중복(행 불어남), 짝 없는 키(조용히 빠짐), 빈 키, 표기 흔들림 |
| `.harness/tools/reconcile.py` | 들어온 행 = 쓴 + 뺀 + 따로 둔 행인지(같은 ID가 여러 번이면 그 횟수까지). 결과 JSON의 rows 목록도 읽음. 종료 코드 0 일치, 1 불일치, 2 검사 0건, 3 실행 오류 |
| `.harness/tools/precheck.py` | 제출 전 키 모양, TODO·FIXME, 이메일·휴대·유선 전화번호·등록번호 모양(값은 가려서 보임). .gitignore에 걸려 검사하지 않은 것도 이름을 보임. 종료 코드 0 없음, 1 있음, 3 실행 오류 |
| `.harness/tools/selftest.sh` | 도구 자체 점검(임시 폴더) |
| `.harness/vendor/chart.umd.min.js` | Chart.js 4.5.1(MIT). CDN 없이 차트 |
| `.harness/LIBS.md` | 문제 유형별 표준 라이브러리·패키지와 함정 |
| `.harness/cheatsheet.md` | 당일 순서와 막힐 때 |

모든 스킬은 `allow_implicit_invocation: false`라서 `$이름`으로 부르지 않으면 동작하지 않습니다.
도구는 표준 라이브러리만 쓰고, 개수는 항상 전체를 셉니다. 화면에 예시만 일부 보일 때는 그렇다고 밝히고, `--all` 또는 `--show 0`이면 전부 보입니다.

## 원칙

- 과제 README와 담당자 답이 이 규칙보다 우선합니다. 과제에 AGENTS.md가 있으면 그 끝에 덧붙이고, 과제 내용이 우선이라고 적습니다.
- 결과물을 대신 만들지 않습니다. 판정 로직과 화면은 과제마다 작업 중에 만듭니다.
- 설치는 하네스 파일만 따로 커밋합니다('chore(harness): 작업 도구 추가'). 과제 작업과 구분되게 하려는 것입니다. 설치 직전 커밋은 `.harness/BASE`에 남겨 마감 검토의 기준으로 씁니다.
- 비밀값, 개인 정보, 과제 자료는 넣지 않습니다.
