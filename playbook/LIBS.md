# 문제 유형별로 쓸 것 (표준 라이브러리 먼저)

원칙
- 아래 방법·수치는 검토할 후보와 사용 예다. README·담당자 기준을 대신하지 않는다. 결과를 바꾸는 기준값은 출처를 확인하고, 미정이면 AGENTS.md대로 묻는다(기준을 세우는 단계는 계획이 $criteria로 표시한다).
- 표준 라이브러리로 되면 그걸 쓴다(웹 서비스는 아래 웹 행대로 고른다). 패키지는 `env_check.py`에 이미 있다고 나왔거나 pip가 될 때만, 넣기 전에 사용자에게 묻는다. pip가 없다는 것만으로 설치 불가로 보지 않고 설치 방법을 확인한다.
- 계산 방법이 결과 품질을 좌우하면 문제를 입력·출력·제약·목적으로 다시 쓰고, 그 구조에 맞는 표준 해법과 단순 기준선을 후보로 잡는다(가장 단순한 방법의 변형만 비교하지 않는다).
- 결과를 사람이 설명할 수 있어야 한다. README·담당자가 요구하지 않으면 블랙박스(랜덤포레스트 중요도, SHAP 등)는 쓰지 않는다.
- 작업 환경의 버전은 `env_check.py`로 다시 본다.

| 웹 서버·검토 화면 | 로그인 없는 화면 한두 개: `http.server.ThreadingHTTPServer`(서버 파일 하나) | 로그인·세션·DB 같은 부품이 필요하면 스택을 미리 정하지 않는다. 과제 기존 코드·README가 정한 스택을 먼저 따르고, 없으면 계획 때 한 번 후보 둘셋(예: 표준 라이브러리만 / 가벼운 라우팅 프레임워크+워커 서버 / 인증·마이그레이션이 딸린 풀스택. 이름은 예시일 뿐)을 동시 요청, 세션·쿠키·CSRF·비밀번호 해시 부품, DB 초기화·재시작 유지, 테스트 클라이언트, 설치·빌드 시간(직접 구현·검증 시간 포함)으로 칸마다 한 줄 표에 비교해 추천 하나와 함께 사용자에게 묻는다(5분 안, 고른 뒤 다시 비교하지 않는다). 고른 버전은 의존성 파일에 고정하고, 컨테이너가 요구되면 그 파일로 설치한다. 고른 직후 설치가 되는지 보고, 안 되면 원인과 대안을 알린다 | 0.0.0.0, 화면 경로는 상대 경로. 요청을 한 번에 하나만 받는 서버(`wsgiref.simple_server`, `HTTPServer`)는 쓰지 않는다. 큰 계산·역직렬화는 요청마다 하지 않고 만들 때 저장한다. 큰 목록은 서버에서 나눠 보낸다(전체를 한 번에 내려 보내지 않는다). 인증 부품은 고른 스택 것을 쓴다. 첫 서버 단계에서 확인한다: 느린 요청 중에 다른 요청을 curl `-w '%{time_total}'`로 보내 기다리지 않는지 / 로그인이 있으면 쿠키(`-c`·`-b`)로 로그인→보호 요청→로그아웃→거부를 스크립트 하나로(curl이 되어도 브라우저는 다를 수 있으니 실제 접속 환경의 로그인 유지는 사용자가 확인한다) / 환경변수로 받는 초기 설정(계정 등)이 빈 저장소와 기존 저장소 재시작 둘 다에서 반영되는지(반영하지 않으면 실행 안내 문서에 방법) |

넣지 않은 것과 이유
- matplotlib 차트: 기본 글꼴에 한글이 없어 깨진다. 브라우저 차트를 쓴다.
- Streamlit, Datasette: 의존성이 많고 미리보기 프록시를 통과하는지 확인되지 않았다.
- statsmodels, scikit-learn, OR-Tools: 설치가 크고(수십 MB), 제한된 작업 시간 안에 결과를 설명하기 어렵다. 표준 대안이 있다.
- 오프라인 wheel 묶음: 작업 환경의 파이썬·glibc 버전을 모른다. 작업 환경에서 pip가 막혀 있으면 그때 다시 정한다.
